## Objective

Create an original first-person combat game in which continuous parries, weapon redirects, and contested firing lines reward recognition and positional decisions. A clean hit is usually lethal; the main opportunity to recover comes from regaining control of the exchange.

## How it works

Unity and C# provide the gameplay foundation, with Blender for original asset and animation production. A deterministic combat state graph governs each interception, both fighters' positions, and their available continuations. Shooting is a committed action that an opponent can disrupt before the firing frame. Readable threat cues, concise death explanations, and immediate retries support mastery.

## Current state

Production scope is confirmed for a finished Windows game intended for Steam, with score attack, training, challenges, and keyboard/mouse and controller support. Constrained duels use contextual stepping and redirects; simultaneous opponents are essential to the release. Cinematic realism will use original characters, assets, and choreography.

The release specification and production plan define internal validation gates before content expansion. Development uses free tools and resources, with no deadline set. Unity project import, combat-data generation, domain checks, and synthetic input transport checks have passed.

The first internal training room established aimed interception, contextual stepping, and earned firing across two opponents using one shared player state. That baseline passed automated simulation, synthetic device-path, and generated-scene checks, produced a Windows development build, and received separate offscreen scene and HUD inspection.

The stop/go tutorial provides unlimited reading and aiming time, spatial callouts, and original Blender rigs for the player and two opponents. This initial paired-pose baseline passed automated combat, synthetic input, scene, and rig-import checks, a Windows development build, and separate offscreen scene and HUD verification.

The Windows 0.3.0 development milestone adds continuous motion and reachable arm IK, with victory requiring separate aimed eliminations of both opponents. The first elimination opens another untimed reading and practice gate. Automated combat, synthetic device, controller/presentation, and rig-import checks passed, including both elimination orders. The Windows build and separate D3D12 offscreen scene/HUD verification passed across all four gates and completion. Authoritative combat continues to decide actual outcomes.

The 0.4.0 internal milestone connects a branching counter exchange in solo and two-opponent rooms. Four threat families each offer two counter routes leading to different openings or sustained binds. Raised and crossed positions have explicit recovery actions. Precommitted enemy policies can lift or block a vulnerable weapon before firing, and the final muzzle line decides each elimination. Controlling one opponent leaves the other dangerous, and the survivor continues attacking.

Untimed lessons identify the actual control point and redirect direction, then visibly play the accepted action before stopping for the next decision. The original Blender library now contains nineteen motions covering anticipation, displacement, binds, release, recovery, firing interference and defeat. Refined dark-suited models improve the silhouette while retaining the native limb, grip and contact geometry. Each run freezes and identifies its combat content for deterministic replay.

Automated combat, scene and original-rig checks passed. Synthetic input through Unity's native keyboard and gamepad paths verified both elimination orders. A separate D3D12 offscreen Windows development player check verified scene and HUD presentation across seven lessons and a two-elimination paired encounter, including survivor pressure.

Human combat playtesting, physical controller flow, composited-window presentation, broader encounter feasibility, final cinematic content, complete score attack and challenge content, and packaged Windows performance still need acceptance. This internal scene is a production gate; finished-release acceptance remains ahead.
